The unified item shows the count, name and status dot without a leading module icon. Without the host, the existing question dock remains available.

## [0.1.0] - 2026-10-03

### Added

- **Interactive question panel.** `ask_user_questions` opens a centered overlay as soon as the tool call arrives: tabbed questions, numbered options with descriptions, multi-select checkboxes, and a `Type something` row for free-form answers. `displayText` renders as Markdown above the options, and a single-question request submits on the option press while several questions walk through a Submit tab.
- **Option preview pane.** An option's `preview` renders as Markdown in a bordered pane beside the options while it is focused, side by side on wide terminals and stacked under them on narrow ones. The pane is titled with the option label in its border, trimmed of the blank lines a preview may carry, and only as tall as what is left after trimming. The pane keeps its place with a `No preview available` placeholder for an option without a preview, and steps aside while the free-form editor is open so typing gets the full width. The block is sized to the room the panel actually has - rows that no longer fit are reported in its bottom border instead of being clipped, and on a terminal too short for even that the pane is left out rather than drawn half-height.
- **Deferred answering, skipping and handover.** Esc closes the panel without settling the request, keeping the focused row and written drafts in `questionManager`, and `⇧S` skips the whole request. The below-editor dock shows `N pending question · <question> · /question to answer`, and `/question` reopens the next pending request with its draft. A request that arrives while a panel is open no longer needs `/question`: answering (or skipping) the current one hands the panel over to the next pending request on its own. A defer is quiet on purpose - it ends the chain and leaves every request pending for `/question` or the next incoming request.
- **Async answers and restart persistence.** The tool returns while the panel stays open; answering or skipping sends a `lune-ask-question-answer` follow-up message (`triggerTurn`, `deliverAs: "steer"`) so the model resumes, rendered as a "Questions answered" or "Questions skipped" row. The message is sent exactly once per settle, and a delivery that fails outright is reported in the UI instead of dropping the answer silently. Pending questions and drafts are snapshotted with `pi.appendEntry` and restored from the active branch on `session_start` and `session_tree`, so a question survives Esc and a Pi restart.
- **Real-TUI observer.** `npm run tui:demo` starts Pi with a scripted faux model that asks one question, for watching the panel, Esc, `/question` and `⇧S` by hand; `LAQ_DEMO=two npm run tui:demo` queues a second request while the first panel is open to watch the handover.
- **README and generated reference images.** `npm run docs:images` renders the README screenshots (`docs/question-panel.png`, `question-dock.png`, `question-answer-row.png`) from the real panel, dock and answer-row renderers against Pi's dark theme palette, and the package declares its gallery image. The images are regenerated by one command instead of re-photographed, so they cannot drift from the UI. Needs `rsvg-convert`.
- **Mouse support for tabs and the editor.** In pi's fullscreen mode (the default since pi 1.0.0) a click on a tab switches questions and a click in the open editor moves its cursor. Option rows stay keyboard-only: a click neither focuses nor confirms one, and a press that hits no tab or editor is left to pi's text selection, so the panel's text can still be copied.
- **Wheel scrolling for the body and the preview.** The wheel scrolls the body, so a question or `displayText` taller than the panel can be read from the top instead of only around the focused row, and over the preview pane it scrolls the preview, whose border now reports rows hidden above and below. The next key or a tab switch returns the body to the focused row.

### Changed

- **`displayText` and `options[].preview` have separate jobs.** `displayText` is the context every option shares - a diff, an excerpt, the values in play - while a preview belongs to one option and changes with focus, so the same block does not have to be written into both. The old wording described the two as equally suitable for code and snippets, which invited the model to duplicate them.
- **A new question outranks one that was only deferred.** The panel picks the least recently shown pending request, so a question that just arrived surfaces immediately instead of an older one the user dismissed with Esc; requests that were never shown keep their creation order. `/question` and the below-editor dock follow the same order.
- **BREAKING: every question now needs a short `header`.** `ask_user_questions` requires a subject label per question (`Storage`, `Auth`, `Timeouts`) and the panel shows it as the tab label, on the submit row and on the answer row; the generated `Q1`/`Q2` numbering is gone from the panel, the tool result and the follow-up message. The header is required rather than derived from the question text, because a truncated sentence reads worse in a tab than a label and a number says nothing about where the tab leads.
- **The panel is only as tall as its content.** The body no longer pads itself to a fixed height or stops at a fixed row cap: a request is rendered whole while the terminal has room for it, and only scrolls when it genuinely does not fit the screen. A short question therefore covers as little of the transcript as possible, and a long one is not clipped to an arbitrary number of rows.
- **The free-form row no longer mirrors typing.** `Type something` stays in place while the editor is open and the row shows an answer only once it is committed, so it no longer rewrites itself on every keystroke or follows edits to an answer that was already written. The draft is untouched: it still lives in the editor, survives Esc, and is restored with the request.
- **Typing on the free-form row opens the editor.** Focusing `Type something` and pressing a printable key starts the answer without `Enter` first, and on that row the single-key shortcuts are text while they keep working on the option rows and on the submit tab.
- **`options[].example` is now `options[].preview`.** The field holds Markdown and renders in a pane beside the options for the focused option instead of as one grey line under every option, which is what makes code, config blocks and mockups comparable before answering. A preview is display input only: it is never echoed into the answer the model receives.
- **Extension surface.** The scaffold's placeholder `ask-question` tool and `/ask` command are replaced by `ask_user_questions` (model-only, sequential) and `/question`; outside the interactive TUI the tool reports that plain text is required instead of waiting for an answer that can never arrive.
- **The model-facing tool result is a status line.** `ask_user_questions` no longer echoes the request id or repeats the questions, which are already in the tool call's own arguments; the id stays in the result `details` for the UI.
- **The answer message stores only what the transcript shows.** `details.questions` carries the header, the prompt and the option labels instead of the whole question, so a `displayText` or an option `preview` no longer stays in the session file forever.
- **Peer dependencies follow the Pi package contract.** The host-provided packages stay on the `"*"` range Pi requires, and the redundant `peerDependenciesMeta.optional` is gone: Pi already suppresses peer installation, and an extension cannot run without them. `devDependencies` names the versions this release is tested against, currently Pi 1.0.0.

### Fixed

- **An answer survives until the session really carries it.** `pi.sendMessage()` only queues a steered message and can drop it, while the answered request left the durable snapshot the moment it settled - so an answer lost from pi's queue was gone for good. Settled answers and skips now stay in a durable outbox until the session branch holds their `lune-ask-question-answer` message (matched by `requestId`); a restore retries delivery while it is missing and releases the entry once it is there.
- **The tab strip no longer scrolls out of view.** When a request's content was taller than the panel's height cap, the body scrolled and took the tabs with it, leaving a multi-question panel with no way to see or reach the other questions. The strip is now pinned above the scrolling body, which itself only appears when the content does not fit the terminal.
- **A large paste survives Esc and a restart.** The draft was captured with `Editor.getText()`, which returns a `[paste #1 +12 lines]` marker for any paste over ten lines or a thousand characters; that marker was what got restored, and the pasted answer was gone. Capture now uses `getExpandedText()`, so a pasted answer comes back whole.
- **A session start does not render into the session that replaced it.** Listeners were replaced after the state reset, so clearing the old state woke the previous session's still-subscribed listener and drew a dock through its context. They are replaced before any change that would wake them.
- **A stale panel cannot take over the panel that replaced it.** Overlay ownership was a boolean that a session boundary cleared, so a panel that resolved after `/reload`, `/resume` or `/tree` released - and its loop kept using - the panel of the session that had replaced it. Opening is now guarded by a generation and an owner token, and `session_tree` resets them the way `session_start` does, so `/question` still opens after a tree jump.
- **Skipping works on a free-form question.** A free-form request opens its editor immediately and the editor turns printable keys into text, so a plain `s` could never reach the skip shortcut - while the footer advertised it. Skip is now `Shift+S`, and a plain `s` is always the letter it is; the one place that asks for `Enter` first is a `Type something` row whose answer starts with a capital `S`.
- **Shift+S skips on terminals using the Kitty keyboard protocol.** The shortcut only matched the literal `"S"` byte, but a kitty-protocol terminal reports a modified key as a CSI sequence such as `\x1b[115:83;2u` instead, so skip was unreachable there while the footer advertised it. The key is now matched through pi's own key parser, which accepts every spelling of `Shift+S`.
- **A failed snapshot no longer sticks the panel.** `Esc` wrote the snapshot before closing the overlay, so a throwing `appendEntry` left the panel up with no way out, and the same throw could cut short a shutdown or a tree switch. Persistence now reports the failure instead of raising it, and the overlay closes either way.
- **The dock follows the request `/question` would reopen.** `markShown` moved a request behind the ones it had already been shown after without emitting an event, so the dock could name one question while `/question` opened another. It now emits `request-shown`, which also writes the new order to the session immediately instead of at the next settle point.
- **A snapshot that could not be written is reported.** Listener failures were swallowed, which could hide a persistence error while the in-memory state moved on. The manager reports them, and the extension says that the question state could not be saved.
- **The open editor is no longer clipped while the answer grows.** The body window followed the focused option row, so an answer taller than the room left under the question pushed the editor's bottom border, the `Enter to submit` hint and the cursor past the panel's bottom edge - the newest lines looked like they had left the input box. While the editor owns the keys the window now scrolls to hold the whole editor block, falling back to the cursor line when the block itself cannot fit, and a wheel scroll still pins wherever the reader left it.

### Refactored

- **The panel's interaction model and renderer are separate modules.** `QuestionPanelController` owns the draft transitions and the row model, `QuestionPanelRenderer` owns the frame, option rows and preview layout, and `QuestionPanel` is left with input routing, editor ownership and overlay lifecycle. The draft stays the single source of interaction state, so existing exports, behavior and persistence are unchanged.
